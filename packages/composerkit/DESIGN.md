## Overview

A reusable conversation library for desktop chat interfaces. Library defaults and the Inter font are separate, replaceable choices.

## Colors

The semantic table is the component color contract. Each row exports a light and dark color token. `globals.css` resolves the semantic name with `light-dark` so nested theme scopes work. Status text, solid fills, soft fills, and on-solid text are separate roles. Syntax colors use the same contract so a brand theme can recolor code and ANSI output.

The light and dark palettes derive from `lib/theme-variables.ts`. The default accent is #2f8fff. Light mode uses contrast 45, ink #1a1c1f and surface #ffffff. Dark mode uses contrast 60, ink #ffffff and surface #181818. The generator supplies accent backgrounds, focus colors, diff highlights and text-on-accent colors. Keep the generated tokens in sync with these settings. Canvas, surface, control and text roles map to the component theme variables in `styles/globals.css`. File-type colors use the same palette in both modes. Token contrast checks do not replace rendered accessibility checks.

## Typography

Inter is the default font. Heading and body are independently overridable roles with their own sizes, weights and line heights, as are the composer and label metrics. The `xs` to `4xl` sizes are the Electron scale (11, 12, 14, 16, 28, 36, 48 and 72px) with the line-height ratios in `app/globals.css`. Weights run from 300 to 700, with a 430 UI weight. Geist Mono remains an independent starter default. The installed font is wired in `app/layout.tsx`; the exported family names do not load fonts.

## Layout

Use flexible, content-driven sizing and wrapping. The main pane scrolls when its header and composer exceed the available height. `--chat-sidebar-width` defaults to 340px and `--chat-message-max` to 70%. Both are replaceable, not universal requirements. `--chat-content-min-width` defaults to a 320px feasibility constraint. The drawer appears when the shell is narrower than the sum of the two widths. As a replaceable readability constraint, `--chat-content-width` defaults to 46rem. The thread list and composer use the smaller of available width and this preferred width, centered within their padded containers. Consumers can also override component classes and styles.

## Elevation & Depth

Opaque overlay surfaces and visible boundaries are the defaults. Dialog and drawer use `shadow-lg`, `0px 4px 8px -2px #0000001a`. The `xs` to `2xl` shadows, 150, 200 and 300ms durations and the ease curves are theme values in `app/globals.css`. There is no universal modal elevation recipe; the shortcuts dialog is described below. Overlays have no entrance or exit motion by default.

## Shapes

Message, control and overlay radii are set on the user bubble, select trigger and anchored popover respectively. Reuse beyond those parts is a library choice. The `2xs` to `4xl` radii are the radius scale with corner-radius scale 1, replacing the earlier shadcn derived radii.

## Components

Map canvas and ink to background and foreground, surface and ink to card and popover, and ink and surface to primary actions. Map control and ink to secondary, muted and accent; use muted ink for secondary text. Map border and focus to boundaries and rings. Map message and message ink together. Destructive actions use ink on surface with a boundary, rather than an invented error color.

The following recipes are library choices. The main content reuses the card surface with a 0.5rem outer inset and overlay radius. The dialog has a 32rem maximum width, 1rem viewport inset, 1.5rem padding and a black 50% backdrop. Its action row has a 1.5rem top margin and 0.5rem gap. The drawer is capped at the viewport and has 0.75rem padding. The shell trigger has a 0.75rem inset. The thread has 1rem padding and a 1.5rem message gap. The composer has 1rem outer and 0.75rem inner padding, a message radius, separate input and action rows with a 0.5rem gap, and a textarea with a 2.5rem minimum and 12rem maximum height. `--chat-composer-surface` defaults to the light surface and dark control roles and can be replaced. The placeholder uses opaque muted ink. Menu items and select triggers have a 36px minimum height; Button variants have their own sizes. Focus outlines are 2px. Buttons use a 2px ring and 2px background offset. Anchored surfaces have 4px offsets, available-space bounds, scrolling and contained overscroll. Overlay positioners use layer 50, with nested portals ordered by the DOM. The preview uses 1rem page insets, a 0.75rem header gap and a 4px popover offset. Preferences use an 18rem preferred width and 1rem padding. Heading metrics explicitly consume the exported heading size, weight and line height. These recipes are consumer CSS, not exported component schema.

The switch track is 32 by 20px and the thumb 16 by 16px, with 150ms ease-out motion and disabled opacity 0.6. A yellow track against white would be 1.62:1, and a 10% ink mix on white is approximately 1.21:1, so the library uses a 36 by 28px hit area, a primary checked track and a bordered surface unchecked track. Light primary against surface is 17.08:1 and the light border against white is 3.36:1. Dark primary against surface is 17.76:1.

The tooltip has 5px by 12px padding, a 20px radius, 13px by 18px text, a 320px maximum width and a dark rgb(45,45,45) background. Its delay is 150ms and its skip window 300ms. The library uses a 5px offset and 150ms opacity and scale motion. The segmented control is 32px high. Selection has no movement because reliable transform positioning would require measuring. Selected radios use the primary and primary-foreground roles for a contrasting state and readable text. Tabs use a 36px minimum height, automatic activation, and an inset foreground underline to distinguish the selected state. Base UI allows arrow focus on disabled tabs but prevents their activation; its public tabs props do not expose a disabled-focus option. Base UI radio arrows wrap because its radio group has no loop setting. Toasts are based on Sonner and render the unstyled Alert as the card. The list is full width up to 49.375rem and centred at the top, with an 8px gap and no offset. Sonner's 356px width and 14px gap apply only to a bare Toaster. Three toasts show at a time and later ones are transparent and ignore the pointer. A toast stays 4500ms, or until closed when its duration is 0, and then stays 200ms for removal. The countdown pauses while the list is expanded, while a pointer is down on a toast and while the page is hidden, and resumes with the remaining time. Mouse enter, mouse move and Alt+T expand the list; keyboard focus alone does not. Alt+T also focuses the list, a region named Notifications alt+T. Escape collapses it, and focus returns to the earlier element when it leaves the list or the last toast closes. A swipe to the right dismisses a toast. A new toast with an existing id closes the earlier one, which stays for the 200ms removal. In the preview, preference changes reuse one id and name the affected setting, and reset closes it.

The shortcuts dialog is 600px wide and 560px high, with a 25px radius, 20px padding, a 13.3% black backdrop and a 0.5px outline plus a 0 4px 8px -2px shadow. It has an opaque surface, a 1rem viewport inset and a scrollable popup. The entire popup scrolls when text or zoom leaves too little room for a separate list, keeping the title, filter, commands and close control reachable. The panel does not change height, so it has no height transition. The screen text and shortcut list are preview content. Switches affect local state only.

## Do's and Don'ts

Do keep library defaults and consumer adaptations distinct. Do verify rendered contrast, focus and interaction in both modes. Don't turn example dimensions into fixed layout requirements.

## Known Gaps

Complete token counts, universal modal styling, thread spacing, state reachability, active motion, density and full focus and contrast evidence remain open. The shortcuts dimensions describe one dialog, not every modal. Radio wrapping, enabled tooltip keyboard focus, toast behavior, indicator geometry and dialog focus return need more verification. Transparent menus require backdrop compositing. Token-pair linting does not establish rendered accessibility.
